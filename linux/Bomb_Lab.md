## phase2

读反汇编码一定要抓重点，用助教的话，不太能每一行都读懂

首先可以使用strings

strings bomb | grep “%”

可以大致看懂输入格式是6个int以空格分隔（%d）

也可以从函数名 find six numbers中看懂

![](/csapp-lab-pics/Pasted%20image%2020260512145353.png)

首先还是得搞懂一些反汇编码，不然会似懂非懂

167e前面一行stack canary 金丝雀的搭建 代码是 mov    %fs:0x28, %rax 也就是把从操作系统特殊段寄存器%fs里的一个随机64位数mov到rax，再把这玩意移动到0x18rsp，这也就告诉我们这个程序只需要用24位，也就是6个int的大小，恰好对应6个整数。

然后xor把eax清零。

显然call完之后6个整数应该躺在rsp的0x0到0x14中。

第一步比较rsp和0，不相等就炸，那肯定得相等，所以第一个数是0

第二步比较0x4rsp和1，相等就跳，那肯定得相等，所以第二个数是1

169f把rsp移动到了rbx，我们可以理解现在rbx就是rsp

跳16b2后eax是1，加完0后还是1，和0x8rbx（0x8rsp）对比得相等所以还是第三个数是1

跳回16a9发现rbx被加了4，这里想到是在做一个类似循环的实现，估计是斐波那契数列

这里cmp其实就是看上限，可以倒回去看rbp的值是0x10rsp，也就是16，肯定还没到

然后做完全类似的加法，后续数依次是2、3、5

最后验证：最后加到5跳回去又加了4，rbx达到了16，等于了rbp，跳到16c3那边结束了

所以答案就是 0 1 1 2 3 5


## phase3

这个代码很长，开啃！

![](/csapp-lab-pics/Pasted%20image%2020260519185424.png)

依旧金丝雀，直接看16f7

这里把一个占1字节的东西放到了rcx，把4字节的东西放到了rdx，把4自己的东西放到了r8

由于我们输入参数进入寄存器的顺序是rdx rcx 和 r8，所以这里应当是 int char int 的输入

scanf返回的值应当是数量，要检测输入的数是否小于等于2，是则爆炸

对于rdx的值，大于7（ja=jump above）就炸（1826是一个炸），所以必须小于等于7

这里其实第一次看看不太懂，没事注意到最后jmp了，总之不会爆炸，继续往下看

![](/csapp-lab-pics/Pasted%20image%2020260519192419.png)

我们发现下面有7个非常类似的段落（这很有意思，猜到可能是switch-case），此处截取第一个

第一步把105移动给eax，并把121和0x14rsp对比，不相等就炸，那就只能相等，所以r8应当是121

![](/csapp-lab-pics/Pasted%20image%2020260519192639.png)

跳过去后直接把al，其实是rax的1位寄存器，和0xfrsp对比，不相等就炸，然后就结束了

这里rax是什么，就是之前的eax，也就是105，但它是一个char，所以本质是一个ASCII码的读取，也就是105对应的ASCII。背过的话就知道97是a，所以105是i，不知道也没事，man ASCII搞定。

所以合法的答案的后两个应当是 i 121，那第一个呢？结合我们的猜测既然是switch-case，应该有一个case几的体现，结合最前面没看懂的那段，我们再来分析：

172d写的是把rdx+rax * 4的地址对应的值读出来，并移动到rax；再把这玩意和rdx加起来，然后跳到rax对应的地址，所以猜到最一开始rax的决定性很大，大概率是那个case几。在172d之前，rax恰恰是0x10rsp赋予的，所以这玩意应当是case几了，按惯例应当从0开始。

这个时候可能需要试一下，最简单的做法是gdb后b explode_bomb 然后把自己的答案输入进去

如果没有出现defused，那就是有问题，说明程序跳到爆炸但停住了而已。这个时候就ctrl c触发彩蛋就行了，然后反复尝试，应该可以得到正确答案。


## phase4

也很长，包括一个函数func4和具体的phase4，继续啃

我们先看这个phase4，在18d6可以看到它调用了func4，所以phase4是先干事。

从18a5-18bc和phase3非常类似，输入两个东西，然后call sscanf 返回值eax必须等于2，也就是必须输入2个数

同时还强调rsp，也就是rdx，第一个输入的东西，要小于或等于0xe（14）

然后rdx=e，rsi=0，rdi=第一个数，做好准备就调用func4了

此时给到func4的东西是 “第一个数 0 e”

我们也需要看一下他希望这个程序输出什么

注意到call完的18db，把19和返回值寄存器rax对比，不相等就爆炸，所以返回值要是19

我们其实可以先看到18e0这里把之前一直没有操作的第二个数和19比较，必须相等，所以这里其实直接确认了第二个数是19，就差在函数里看出第一个数了

![](/csapp-lab-pics/Pasted%20image%2020260519200349.png)

![](/csapp-lab-pics/Pasted%20image%2020260519195830.png)

这里最好结合草稿纸画图去看

把rdi rsi rdx rbx rax列出来然后看他们的值的变化

第一次的时候 我们先看185b-186b

解释shr是逻辑右移，这里移31位显然是要查看符号位，应该是0；

解释sar是算术右移，这里的1就是除以2，并且后续可以知道，这个数一定能除进

然后就看到第一次结束了之后rbx=7，第一个数要和7对比

如果7大于第一个数（注意比较的顺序）就跳1875这个分支，然后edx=ebx-1（注意这里ebx本身的值没有改变）；7小于第一个数就跳1881另一个分支，然后esi=ebx+1。

接下来最关键的来了，它又重新调用自己。这看着是一个递归，而且看着很像所谓的二分法（显然看不出来）。

想不清楚就假设一个数带进去，然后会发现经过4次调用后会出现既不jg又不jl的情况，也就是会执行ret操作了，相当于找到了那个数

这里我们需要搞清这些：

1、在执行ret之前，先有一步mov ebx eax，也就是把ebx这个存最关键的数的存到返回值寄存器里

2、这里很关键，pop rbx 结合前面push rbx可以知道这是一个callee reserved register，他需要保存进入和出去之前rbx的值。

3、为什么这么说？因为当ret过后，也就是call后面的一步，就需要把返回值和rbx加起来，而rbx每一轮的值都被保存了下来

4、最后的输出是一个4次rbx的和

我们希望这个和是19，而第一次rbx是7，所以我们希望里面加出来是12

如果我们一开始走的分支是输入数大于7的分支，可以做一个这样的计算会发现rbx为11，而缺的这个1是显然做不到的，因为这个1应当是最后二分出来那个确切的数，而那个数已经是大于7了

所以一开始走的是小于7（也不可能等于7，因为7不等于12），计算会发现如果走7rbx是3，所以我们还缺9，接下来如果再小于3会发现要么2要么1，怎么也加不到9，所以肯定大于3

再计算会发现rbx是5，所以我们还缺4，而4小于5，计算会发现恰好成立

所以要输入的就是4

结合前面已经确定的第二个数 我们的输入就是4 19
