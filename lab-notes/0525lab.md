这里我比要求的多做了一些，因为我发现我没搞懂这玩意。

![](/notes-assets-0525/media/image7.png)

如下图，首先我使用export -n

然而我在重新开机、另开新窗口后输入ls却发现还是ll，据资料发现，在启动文件.profile中，会定义一块代码，原文是

if \[ -d \"\$HOME/bin\" \] ; then

PATH=\"\$HOME/bin:\$PATH\"

fi

意思是如果HOME下有bin文件，会自动修改环境变量PATH，在前面加上HOME/bin的路径。这就解释了为什么每次开机echo
PATH都是ll。

因为这对后续实验造成了干扰，需要手动删除文件。

总结来看，因为进程的独立性，ls的改变只适用于本进程，且当其不再为环境变量时，因为子进程会启动fork，而局部变量不会进入子进程的内存，所以无法在子进程中体现。

回答第二个问题：linux如何修改命令路径？

首先，linux检查是不是一个别名；其次，linux检查是不是一个内置命令；然后，linux检索PATH环境变量；最后，linux报错。

![](/notes-assets-0525/media/image8.png)

内置命令（builtin）是指在写在bash源代码内部的函数，与外部命令对比。据资料，原因是要通过修改本shell进程内存等方式实现必须在本shell进程内实现的功能（而不能通过外部命令交给子进程去做，因为子进程无权修改父进程内存），以及提高效率。常见的内置命令有cd等，常见的外部命令有gcc等。可以用type进行查看。

## 3、zombie进程

见代码zombie.c，首先解释代码，fork在子进程的返回值是0，在父进程的返回值是子进程的实际PID（显然大于0），可据此做if-else分支。在我的代码中，子进程exit，但父进程不调用waitpid，并强制睡眠60s，使子进程在这段时间变成zombie进程。

使用ps aux \| grep
zombie观察进程信息，发现zombie处于浅睡眠前台S+，但出现了一个defunct的zombie，STAT显示为Z+，即zombie。

过了60s，systemd会自动回收zombie，因此再输入ps aux \| grep

本质上需要理解的是execve在执行后，子进程的PID不变，但程序就变成了ls，所以不会打印下面那句话。

waitpid的三个参数的含义：第一个pid，就是父进程记下的子进程的pid；第二个&status，status里面放了编码过的退出信息，报错信息等，用linux定义的宏和读指针的方式可以解析；第三个是控制等待方式的选项，0是和wait一样的默认阻塞模式，WHOHANG是非阻塞模式，可以让父进程在子进程没结束时同步做其他工作。

### （3）好多子进程随机入睡

回答问题，首先fork，waitpid在前面都已经解释过了。这里的exit退出的是睡眠时间，用WEXITSTATUS宏可以解析得到。

子进程的fork是按顺序的，但fork完以后人人平等，操作系统调度器面对4个同级的进程，执行的顺序是随机的。

对于最后的退出顺序，取决于waitpid的代码，这里有两种做法。

pid_t child_pid = waitpid(-1, &status, 0);

![](/notes-assets-0525/media/image15.png)

注意到第一个参数是-1，意思是**等待任意一个子进程退出**，所以此时子进程退出的顺序将严格按照睡眠时间长短；如果睡眠时间相同，则按照一开始执行的顺序。

![](/notes-assets-0525/media/image16.png)

然而，经过实验，我发现最后同秒数的子进程的退出顺序呈现相当的规律性，始终是pid小的会先打印出来。按之前的理解，不应该如此，应该是按照前面分配的顺序，谁先开始谁先结束。

但据资料，这里的两个子进程往往会在非常短的间隔（几ns-几μs）exit，对waitpid来讲这个太短了，所以触发了**kernel链表**按PID顺序回收的规律。因此，对于最后的问题，我认为恰恰相反，子进程结束顺序在某种程度上是相当固定的。

另一种情况：

pid_t child_pid = waitpid(pids\[i\], &status, 0);

如果是这样写，那父进程就会等到所有子进程都exit，严格按照顺序输出并回收（i是从0到2按顺序走的，所以最后的输出一定是按顺序的）。这段对应的代码被我以注释的形式也写在了程序里。

![](/notes-assets-0525/media/image17.png)

我尝试加入一个强制睡眠几ms再死的代码（这个不在要求里面）。结果也很有意思。我大概理解了一下，对于第二个4450-4453，比较常规，4451因为睡了5ms所以直接被排到了最后。而4445-4448就很有意思了，4447最后打印sleep却最先打印exit，由于并行的随机机制，可能是因为4448在打印完sleep后还没来得及sleep就被time
interrupt了（我猜测），然后移交给了4447直接做完了打印和sleep，导致4448比4447最后要慢了。而最后可能又恰好赶上4446和4448几乎同时结束，两者按kernel的PID顺序打印出来。

### （1）观察

Echo \$？表示输出上一个命令的退出码（即exit（）里面那玩意）

当ls的时候，正常退出，为0

当ls一个不存在的file或directory的时候，严重错误，为2

非0表示的是不正常退出

### （2）test_status.sh

#!/bin/bash

mkdir testdir

if \[ \$? -eq 0 \]

then

echo \"Directory created\"

else

echo \"Directory already exists\"

fi

![](/notes-assets-0525/media/image19.png)

程序的意思大概是创建一个新文件夹testdir，如果退出码是0就directory
created否则就directory already
exists，这非常好理解，因为如果已经有了一个文件就无法创建同名文件，此时退出码必然不是0（据测试，为1）。

### （3）&&和\|\|

![](/notes-assets-0525/media/image20.png)

&&是与，在这种情境下就是前面对（success，\$?=0）后面就输出；\|\|是或，在这种情境下就是前面不对（\$?!=0）后面就输出。

## 6、多进程随机性

![](/notes-assets-0525/media/image21.png)
